# 玩法设计工作区

版本：V1.2

日期：2026-11-24

阶段：首轮公开研究与规范完成，首批四项方向已获用户确认；具体规则尚待讨论，未修改游戏实现。用户要求当前先完成交接，由另一位协作者继续。

协作者接手先读仓库根目录 [Agent.md](../../Agent.md)。研究中的推荐不等于已确认设计；涉及判断先研究或尝试，再成批交用户决定。

## 阅读与使用

1. [公开资料与案例研究](01_公开资料与案例研究.md)：区分实际 GDD、设计方法和产品说明，明确能借鉴什么。
2. [玩法设计工作规范](02_玩法设计工作规范.md)：规定怎么写、怎么试、何时需要用户确认；不规定游戏必须采用哪种玩法。
3. [现状评估与待确认](03_现状评估与待确认.md)：从已有代码和设计出发，讨论核心乐趣、循环、战斗参与和自由装配。
4. [决策记录](decisions/决策记录.md)：查看哪些已确认，哪些还不能实现。
5. [系统规则卡](templates/系统规则卡.md) 与 [玩法试验记录](templates/玩法试验记录.md)：用户确认范围后复制使用，模板不是已完成设计或试验。

来源取证在 `research/`，正文优先记录必要事实与短引文，不整份搬运外部受版权保护文档。链接访问成功不代表观点已被验证，商品说明也不能冒充完整策划案。

## 后续如何扩展

用户确认核心循环后，再按实际需要增加体验概念、核心循环、组装、战斗、挑战内容、成长与验证记录。现阶段不批量建空文档，也不预建大世界、赛季、付费等未经确认的开发模块。

已确认规则最终回写 [DESIGN.md](../DESIGN.md)，涉及数据与协议时同步 [INTERFACES.md](../INTERFACES.md)。同一规则只保留一个当前有效定义，其余文档通过链接和 ID 引用。

## 维护与同步

- 初版交付为 V1.1；本入口、现状评估与决策记录回填首批确认后为 V1.2，其他取证和模板仍为 V1.1。正式设计的文档维护版本现为 V1.1，保留旧 v0.1 来源。实际修订再升版，末尾记录日期。同一文档历史文件最多保留最新三个，Git 提供完整历史。
- 新增材料、规则确认、试验结果或同步状态变化后，立即更新根目录 `Agent.md`。
- 本地提交与 GitHub 推送分别记录。当前认证情况及待办以 `Agent.md` 为准。
