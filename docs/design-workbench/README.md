## 阅读与使用

1. [公开资料与案例研究](01_公开资料与案例研究.md)：区分实际 GDD、设计方法和产品说明，明确能借鉴什么。
2. [玩法设计工作规范](02_玩法设计工作规范.md)：规定怎么写、怎么试、何时需要用户确认；不规定游戏必须采用哪种玩法。
3. [现状评估与待确认](03_现状评估与待确认.md)：从已有代码和设计出发，讨论核心乐趣、循环、战斗参与和自由装配。
4. [装配体验与组合设计讨论稿](04_装配体验与组合设计_讨论稿.md)：六部位跨动物+机械零件库、拼色融合、叠阶与 8 组特殊组合的共创底座。
5. [总闭环与双循环架构](05_总闭环与双循环架构.md)：宏观双循环（单机肉鸽手操 × 「万坤封神榜」异步快照排位）、局内/局外两层资源流与长线扩展接口（已闭合）。
6. [世界观引导剧情与生物进化图鉴](06_世界观引导剧情与生物进化图鉴.md)：巴别进化巨塔长线多章世界观、全项目统一中二名词词典、蛋壳 0 号 5 步教学文案与《万象进化秘典》科普规格（已闭合）。
7. [单机关卡体系与关卡奖励](07_单机关卡体系与关卡奖励.md)：双入口推进、硬核一命肉鸽死亡规则、第一章 8 关与 36 件实际零件全量映射、三重奖励、巴别无尽深渊与每周狂想变异赛（已闭合）。
8. [对战排位体系与对战奖励](08_对战排位体系与对战奖励.md)：「万坤封神榜」关档分池单挑天梯、7 大中二玩梗段位、确定性自动 AI 行为与战报、四重零碾压奖励与 4 周赛季归档（已闭合）。
9. [数值体系与经济平衡模型](09_数值体系与经济平衡模型.md)：裸鸡 `HP=100/ATK=10` 基准、边际递减护甲、Lv1~3 叠阶与躯干拼色折算、多主动技分键融合、36 件全量定标、8 关 TTK 曲线与原初源质 3~5 小时轻爽毕业账本（已闭合）。
10. [MECE 需求覆盖与交互矩阵](10_MECE需求覆盖与交互矩阵.md)：端到端主流程状态机、7 大系统域 × 5 运行态全覆盖矩阵、16 组跨系统冲突裁决与全需求验收台账（已闭合）。
11. [决策记录](decisions/决策记录.md)：查看哪些已确认，哪些还不能实现。
12. [弹簧腿规则卡](rules/部件_弹簧腿.md)：逐件讨论的早期单件卡；跳跃与离地命中已并入 `09`/`10` 统一规则。
13. [系统规则卡](templates/系统规则卡.md) 与 [玩法试验记录](templates/玩法试验记录.md)：后续细化单件/试验时可复制使用。

来源取证在 `research/`，正文优先记录必要事实与短引文，不整份搬运外部受版权保护文档。链接访问成功不代表观点已被验证，商品说明也不能冒充完整策划案。

## 后续如何扩展

用户确认核心循环后，再按实际需要增加体验概念、核心循环、组装、战斗、挑战内容、成长与验证记录。现阶段不批量建空文档，也不预建大世界、赛季、付费等未经确认的开发模块。

已确认规则最终回写 [DESIGN.md](../DESIGN.md)，涉及数据与协议时同步 [INTERFACES.md](../INTERFACES.md)。同一规则只保留一个当前有效定义，其余文档通过链接和 ID 引用。

## 维护与同步

- 实际修订才按有效工作日升版，末尾记录日期；各文件版本以其头部为准。正式设计保留旧 v0.1 来源。根目录 `Agent.md` 维护当前文件与状态；同一文档历史文件最多保留最新三个，Git 提供完整历史。
- 新增材料、规则确认、试验结果或同步状态变化后，立即更新根目录 `Agent.md`。
- 本地提交与 GitHub 推送分别记录。当前认证情况及待办以 `Agent.md` 为准。
