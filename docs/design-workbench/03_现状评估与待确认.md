## 2. 对前轮结论的校准

此前只试了少量配装，并且敌人会随玩家属性变化。因此：

- 可以确认当前环境不适合直接比较正式配装强弱。
- 可以提出“堆件的代价不足、可能存在支配策略”的风险。
- 不能据此证明“全装在所有条件下最强”，也不能直接选定硬容量、点数预算等治理方案。
- 少量模拟的胜负不等于玩家体验验证；飞行或高度轴也只是候选解法，不是必须实现的结论。

后续如验证堆件风险，应固定敌人、内容版本、规则和随机条件，覆盖加装/移除、重复件与典型组合，并记录反例。试验范围与评价标准须先确认。

2026-11-24 用户已通过问卷确认：

|---|---|---|

完整确认范围见 [决策记录](decisions/决策记录.md) P-001~P-004。下面保留原讨论维度供追溯，不代表重新打开已确认问题，也不代表所有候选均获批准。

### Q1：最希望玩家因为什么而反复组装？

- 创意拼装与试验：奇怪外形、行为变化、意外组合更重要；需验证多件组装是否持续产生新结果。
- 看懂对手并找到解法：威胁、取舍、克制和复盘更重要；需验证同一挑战是否存在多个可行解。
- 探索中获得零件并改造：发现、回收、损坏和返程更重要；需要额外的世界与资源循环。

原讨论维度可以并存；现已确认创作与组合发现优先，不再替用户改排序。

### Q2：第一条完整循环先采用哪种结构？

- 固定挑战/连续关卡：保留现有方向，便于比较同一敌人下的改装效果。
- 每局轮次组装对战：每轮出现新选择，再战斗，直到本局结束；是否有商店或资源另议。
- 探索遭遇与返程：发现零件、组装、战斗、继续深入或回去；增加移动、携带和世界状态问题。
- 暂不选型：先做纸面走局对比，用户看完典型流程后再决定。

这决定先写哪份循环，不自动取消其他候选方向。

### Q3：希望玩家在战斗中参与到什么程度？

- 全自动：战前组装承担主要决策，战中重在观察结果。
- 自动加一次主动技：保留旧设计方向，明确技能时机如何改变结果。
- 更多战中操作：需进一步确定操作种类和频率，也需重新评估短时游玩与异步对战。
- 暂保留旧设定：先把组装到战斗的因果写清，再决定是否改控制方式。

旧设计记录的是“自动 + 每局一次技能”，实现没有实际使用入口。用户现确认纯自动，已回写正式设计；代码中的旧能力字段仍在，未擅自改为被动或自动释放。

### Q4：怎样理解当前自由装配？

“全部零件可用”和“可以无限加装”是两个独立问题。

- 所有零件可用，保留多件组装；允许研究有取舍的限制，具体方式下一批再确认。
- 所有零件可用，先保留近乎自由堆叠；先验证其是否真的造成问题。
- 更偏重收集/成长；愿意重新讨论 M0/M1 不做解锁的旧约定。
- 先做对比试验，再确认自由装配边界。

不能因为竞品有商店，就自动引入货币；也不能因为要保留十条腿的创作乐趣，就默认堆件不能有任何代价。

## 4. 后续问题池，按前一批答案展开

| 问题组 | 需要确认的内容 | 为什么暂不直接定 |
|---|---|---|
| 玩家与游玩场景 | 面向谁，一次玩多久，可中断到什么程度 | 决定复杂度和节奏目标 |
| 战前信息与挑战 | 提前看到什么，固定/随机敌人，是否允许针对改装 | 决定选择是推理、风险还是试错 |
| 装配规则 | 重复件、尺寸/重量/预算、协同与冲突、合成 | 依赖自由装配目标 |
| 战斗模型 | 攻击方式、范围/位置、技能、速度用途、同时结算 | 依赖主循环和操作定位 |
| 胜负与恢复 | 平局、超时、失败损失、重试、存档 | 影响流畅性与试错意愿 |
| 成长与内容 | 关卡、轮次、材料、解锁、随机性 | 不能与“全开放”约定静默冲突 |
| 长期分支 | 大世界、多单位、异步/实时 PvP、商业化 | 先评估是否服务已确认体验，不预设必做或不做 |
| 验证判据 | 怎样算组合有效、过程顺畅、值得继续 | 体验判断与阈值须由用户确认 |
