# FRAMESHIFT — 生物视觉规格（CREATURE）

> 面向：B（界面与呈现）。本文只回答一个问题：**怎么把零件链画成一只像活着的生物。**
> 不改规则、不改交互、不改 `src/core/**`。所有数值都可以直接抄进代码。
>
> 目标文件：`src/ui/creature.ts`（重写内部）、`src/ui/parts-art.ts`（保留静态零件，
> 新增关节肢体 / 翅膀两个绘制分支）。对外签名不变：
> `buildCreature(phenotype)` / `drawCreature(ctx, layout, x, groundY, scale, state)`。

---

## 0. 观感基准

**要的感觉**：一只从显微镜培养皿里爬出来的、瘦长的、分节的实验体。
身体有骨架感（一节一节），腿有髋/膝/踝三个关节点，走路时脚掌真的踩在地上，
翅膀有前缘骨和半透明膜，眼睛会眨，鳃在颤，发光器在呼吸。

**明确的失败样式（当前实现的问题，逐条修掉）**
1. 圆角胶囊 + 零件悬浮在旁边 → 改成：**分节脊柱 + 体节重叠**，零件锚定在脊柱上（§2）。
2. 腿是一个小图标 → 改成：**两段骨骼 + 两关节 + 脚掌**，由 IK 驱动（§3.5、§4.1）。
3. 零件像贴纸，没有遮挡/远近 → 改成：**三层景深**（远侧肢体 65% 透明度 → 身体 → 近侧肢体）。
4. 不动 → 改成：呼吸 / 眨眼 / 鳃颤 / 发光脉冲 / 翅膀扇动，全部用 `t` 秒驱动（§4）。
5. 太小 → 身体长度公式放大 20%（§5）。

**一条硬规则**：所有形状只用 `fill` + `stroke`（+ 必要的 `shadowBlur`），
**不加载任何图片/字体**，不使用 `filter: blur()`、不使用离屏视频。

## 1. 坐标系与画布约定

沿用现有调用约定，**不改变**：

```
drawCreature(ctx, layout, x, groundY, scale, state)
```

- 调用前 `ctx` 已 `setTransform(dpr,0,0,dpr,0,0)`，单位是 **CSS px**。
- `(x, groundY)` = 生物**脚底接触点**（身体中心正下方）在屏幕上的位置。
- `scale` = 舞台缩放（stage 传 `creatureScale`，缩略图传 0.3~0.9）。

**内部局部坐标系（所有 §2~§4 的数字都在这个系里）**

| 项 | 定义 |
|---|---|
| 原点 | 脚底接触点（= 屏幕 `(x, groundY)`） |
| +x | 生物**前方**（向右跑） |
| +y | **向下**（Canvas 惯例），所以"向上"是负 y |
| 单位 | 参考像素；`U = H / 48` 是所有细节的统一缩放因子（H 见 §2.1） |
| 地面 | `y = 0` |

绘制入口统一做：

```ts
ctx.save();
ctx.translate(x, groundY);
ctx.scale(scale, scale);
// 之后全部用上表坐标；不要在内部再乘一次 scale
...
ctx.restore();
```

**裁剪**：舞台侧把生物画在一个 `ctx.save(); ctx.beginPath(); ctx.rect(0, 0, w, h); ctx.clip();` 里。
翅膀/长腿可能超出画布，超出的部分必须被裁掉，否则会在 HUD 上留残影。

**DPR**：调用方已经处理（`canvas.width = round(cssW*dpr)`）。
**不要**在 `drawCreature` 里再乘 dpr；只有离屏精灵（§7.3）需要自己乘。

## 2. 解剖：脊柱、体节、身体轮廓

### 2.1 尺寸公式（用零件数 n 表达）

```
n  = phenotype.size                // 3 ~ 12，实测两关是 7 / 8
H  = clamp(32 + 1.6 * n, 32, 52)   // 体厚（身体最大高度）
L  = clamp(104 + 15 * (n - 1), 104, 264)  // 体长（脊柱弧长近似）
U  = H / 48                        // 细节单位：所有零件尺寸都乘它
```

| n | 3 | 4 | 5 | 6 | 7 | 8 | 10 | 12 |
|---|---|---|---|---|---|---|---|---|
| H | 36.8 | 38.4 | 40.0 | 41.6 | 43.2 | 44.8 | 48.0 | 51.2 |
| L | 134 | 149 | 164 | 179 | 194 | 209 | 239 | 264 |

> 比现有 `60 + 14n` 大约 **+20%**，这是"读不清零件"的主要修正项之一。

### 2.2 脊柱曲线

脊柱是从**尾尖 (s=0)** 到**头端 (s=1)** 的一条浅拱曲线，身体中心在 `(0,0)`：

```
A  = 0.09 * H                       // 拱高，H=44.8 时约 4.0px
P(s) = ( -L/2 + s*L ,  -A * sin(π * s) )     // s ∈ [0,1]
T(s) = 切线方向角 = atan2( dP.y/ds , dP.x/ds )
       dP.x/ds = L
       dP.y/ds = -A * π * cos(π * s)
```

**采样**：`SAMPLES = 32`，预计算 `sx[33] / sy[33] / tan[33]` 三个 `Float32Array`，
放在 `buildCreature` 里算一次，**不要**每帧重算三角函数。

**任意 s 的取值**：`k = s*32`，`i = floor(k)`，`f = k-i`，线性插值。
锚点位置和朝向都从这两个数组插值，避免每个零件调用一次 `Math.sin`。

### 2.3 体厚剖面（决定"像不像生物"的关键）

半径是**半厚**：`r(s) = 0.5 * H * profile(s)`

| s | 0.00 | 0.06 | 0.14 | 0.26 | 0.40 | 0.56 | 0.70 | 0.82 | 0.92 | 1.00 |
|---|---|---|---|---|---|---|---|---|---|---|
| profile | 0.10 | 0.34 | 0.62 | 0.86 | 1.00 | 1.00 | 0.94 | 0.80 | 0.62 | 0.34 |

实现：9 段线性表 + `lookupProfile(s)`，不要用 `sin` 拟合（尾巴会太圆）。
读法：尾尖很细、胸口最厚、头端收细成颈，最后再被头部盖住。

### 2.4 体节（把胶囊变成"一节一节"）

```
Nseg = clamp(round(L / 23), 5, 13)        // L=209 → 9 节
中心 s_k = (k + 0.5) / Nseg                // k = 0..Nseg-1
rx_k    = (L / Nseg) * 0.70                // 0.70 < 1 才有重叠
ry_k    = r(s_k)
rot_k   = T(s_k)
```

每节是一个**旋转后的椭圆**，按尾→头顺序画。**先描边再填充**：

1. 对每节 `ctx.ellipse(...)` + `stroke()`（描边色见 §6），
2. 再对整个形状 `fill()`（不透明渐变）。

填充会盖掉内部描边，只留**外轮廓**，于是得到"一体成型但分节"的身体。
之后再补 3 条"节间缝"（见 §2.6）。

### 2.5 头

`s=1` 端是一个更大的圆头，**它属于 `head` 零件**（`parts[0]` 永远是 head，所以每只生物都有头）。

```
头中心 s_h = 0.96
半径：rx = 0.62 * H,  ry = 0.58 * H      // H=44.8 → 27.8 × 26.0
```

头的**细节**（由 head 零件绘制，见 §3.1）：眉脊、下颌线、鼻孔、口腔阴影。
**没有 eye 零件的生物就是没有眼睛的**——这是基因决定的，不要"补一个默认眼睛"。

多头生物（链内第二个 AUG）：第 k 个 head 的锚点 `s = 0.96 - 0.10k`，
半径乘 `0.72^k`，并且这些都是**附着在身体上的瘤状头**，不是独立身体。

### 2.6 节间缝与背线高光

- **节间缝**：每两节之间，在身体下半侧画一段短弧：
  `arc(中心 P(s_k), r(s_k)*0.92, 0.25π, 0.75π)`（只画下半圈），
  颜色 `rgba(6,14,20,0.38)`，线宽 `1.1*U`。
- **背线高光**：沿脊柱上侧偏移 `-0.46*H` 画一条二次曲线，从 s=0.15 到 s=0.86，
  颜色 `rgba(143,227,220,0.16)`，线宽 `2.2*U`，两端 `globalAlpha` 渐隐（分 3 段画）。

### 2.7 锚点映射表（零件 → 脊柱位置 / 朝向 / 尺寸）

> **通用分布 vs 分类分布。** 如果只按全局序号排，公式是
> `s_i = 0.94 - 0.80 * (i / max(1, n-1))`；8 个零件时每 0.11 一段，
> 结果必然是"甲片和腿挤在同一条带子上、尾巴空一半"。
> 所以下面按**类别内**的 `j / m` 分布，全局 `i / n` 只用于相位与高亮。
> 两者是同一件事的两种精度：类别分布 = 通用分布 + 每条带子各排各的。

`s` = 脊柱参数；`j` = **该类别内**的序号，`m` = 该类别的零件总数；
`k` = 同类里"第几个"（用于多头/多眼）。

| 零件 | s 公式 | 朝向 | 尺寸（参考 px，乘 U） |
|---|---|---|---|
| `head` | `0.96 - 0.10k` | 沿切线 | `rx 0.62H, ry 0.58H`（见 §2.5） |
| `eye` | `0.93 - 0.09k` | 贴头，向斜上 | `r 7.5`（瞳孔 3.2） |
| `horn` | `0.88 - 0.07k` | 向上偏后 16° | 底 7，长 16 |
| `antenna` | `0.91 - 0.06k` | 向上偏前 34° | 两段 12 + 10 |
| `leg` | `m>1 ? 0.70 - 0.44*(j/(m-1)) : 0.56` | 向外（下） | 见 §3.5 表 |
| `longleg` | 同上 | 向外（下） | 见 §3.5 表 |
| `claw` | 同上 | 向外（下） | 见 §3.5 表 |
| `fin` | 同上 | 向外（下） | 见 §3.5 表 |
| `shell` | `m>1 ? 0.34 + 0.46*(j/(m-1)) : 0.56` | 向外（上） | 20 × 9 甲片 ×3 |
| `spike` | `m>1 ? 0.30 + 0.50*(j/(m-1)) : 0.52` | 向外（上） | 高 11~13 |
| `crest` | `m>1 ? 0.28 + 0.54*(j/(m-1)) : 0.55` | 向外（上） | 5 齿，高 8~12 |
| `wing` | `m>1 ? 0.66 - 0.26*(j/(m-1)) : 0.58` | 向上偏后 22° | 前缘 22，膜 30×18 |
| `glow` | `max(0.05, 0.16 - 0.07j)` | 向外（上） | 泡 r 6，光晕 16 |
| `maw` | `0.90` | 向前 | 弧 r 8 + 8 齿 |
| `sac` | `0.26` | 向外（上） | 15 × 12 |
| `gill` | `0.44 - 0.08j` | 向外（下） | 3 条缝，长 12 |

**统一取框**：`frameAt(s)` = `translate(P(s)) * rotate(T(s))`。
朝向为"向外（下）"的零件，直接在这个框里用 +y 表示"离开身体"；
朝向为"向外（上）"的零件，额外 `scale(1,-1)`，这样两套零件都能用同一条
"+y = 远离脊柱"的约定，绘制代码不用写两份。
**四肢与翅膀的锚点**要往身体里缩：`y = +0.26H`（髋/肩埋在体腔内），
这样关节被身体盖住，看起来是"长出来的"而不是"插上去的"。

### 2.8 边界情况（不许崩）

| 情况 | 处理 |
|---|---|
| `n < 3` | 公式照算（H=32, L=104），身体很短但成立；不要特判 |
| `n > 12` | `L` 封顶 264；超出部分在各自类别里继续等距塞，最小间距 `0.055`（归一化），允许重叠 |
| 某类别 `m = 0` | 整个类别跳过（`continue`），不要产生 `NaN` |
| 某类别 `m = 1` | 用表里的单值分支（例如腿 `s = 0.56`） |
| `parts.length === 0` | `drawCreature` 直接 `return`（现有代码已这么做，保留） |
| `L/H < 2.2` | 说明数据异常，按 `L = 2.2H` 兜底，避免体节互相吃掉 |

## 3. 16 个零件的画法

**局部坐标约定（先读这条，后面所有坐标都遵守）**

零件一律画在 `frameAt(s)` 框里，**+x = 朝向身体前方，+y = 离开体表**（外法线）。
于是同一个函数既能画腹侧也能画背侧：

| 零件 | frame 是否翻转 | +y 指向 |
|---|---|---|
| `leg` `longleg` `claw` `fin` `gill` `maw` | 不翻转 | **向下**（腹侧） |
| `horn` `antenna` `spike` `crest` `wing` `glow` `sac` `eye` | `scale(1,-1)` | **向上**（背侧/头顶） |

因此 `leg` 的脚在 `+y` 方向，`wing` 的翼尖也在 `+y` 方向——**两套坐标里都是"往外长"**。
`eye` 的瞳孔偏移例外：它在**屏幕坐标**里算，不受翻转影响。

通用规则（每条都成立）：

- 局部坐标原点 = 锚点；**+y = 远离脊柱**；所有数字乘 `U`。
- 每个零件 = **1 个填充 + 1 个描边 + 1 条高光**，颜色见 §6。
- 描边宽 `1.4 * U`（头/甲 `1.6 * U`），`lineJoin/lineCap = 'round'`。
- 轮廓自检：把整只生物填成纯黑，在 0.4 缩放下**每个零件都要能认出来**；
  认不出的形状，优先加长/加尖，而不是加细节。
- 所有零件按 `growth`（0..1）做缩放长出，锚点不变。

### 3.1 `head`（A 家族，起点）

> **例外**：head 用**身体局部坐标**（原点 = 头锚点，+y 向下），不做翻转；
> 下面坐标里的负 y 就是"往上"。

1. **颅骨不再重画**：身体最后一节（§2.4/§2.5）已经是头形，head 只在这上面加细节。
   只有 `k > 0` 的多余头才需要单独画一个 `0.72^k` 的圆 + 一圈家族色描边。
2. 眉脊：从 `(-0.30H, -0.22H)` 到 `(0.34H, -0.16H)` 的二次曲线，
   `strokeStyle rgba(233,242,248,0.22)`，线宽 `2.4U`。
3. 下颌：从 `(0.10H, 0.26H)` 到 `(0.58H, 0.10H)` 的二次曲线（控制点 `(0.42H,0.30H)`），
   用深色 `rgba(6,14,20,0.55)` 描，线宽 `1.6U`，末端加一个小三角"颏突"。
4. 鼻孔：`(0.52H, -0.02H)` 处一个 `1.6U` 的椭圆，填充 `rgba(6,14,20,0.6)`。
5. 高光：左上 1/4 圆弧，`rgba(255,255,255,0.20)`，线宽 `2U`。
6. 多头：半径 `×0.72^k`，锚点见 §2.7，细节只画第 1 个。

### 3.2 `eye`（A 家族）

- 眼窝：圆 `r 7.5`，填充 `#0a161e`，外圈 `r 8.6` 描家族色 `1.5U`。
- 虹膜：圆 `r 4.6`，填充 `rgba(95,227,200,0.55)`（固定用强调青，不用家族色，
  这样眼睛在紫/橙的身体上也能读出来）。
- 瞳孔：椭圆 `3.2 × 3.6`，纯黑 `#050b10`，位置 = 眼窝中心 + `pointer` 方向偏移
  `2.2U`（沿用现有 `pupil` 逻辑）。
- 高光：瞳孔偏移左上 `(-1.4U,-1.6U)` 半径 `1.2U` 白点，`alpha 0.85`。
- **眨眼**：上眼睑是一块与身体同色的矩形，从上方盖下来，
  `lidY = -8.6 + 17.2 * blink`（blink 0=全开 1=全闭），见 §4.3。
  闭眼瞬间瞳孔停在高光位置不动（别让它消失）。
- 多眼：沿 `s = 0.93 - 0.09k` 向后排，尺寸 `×0.85^k`。

### 3.3 `horn`（A 家族）

- 底面半圆 `r 7`（贴着身体），从底面伸出两条曲线到尖端 `(0, 16)`，
  控制点 `(±3.5, 9)`：得到一个略弯的角（+y 向上）。
- 填充 `#3d3120` → 尖端 `#f2b24b` 的线性渐变（尖端更亮，像角质透光）。
- 描边家族色 `1.5U`；沿中线加一条 `rgba(255,224,163,0.35)` 的高光。
- 整体向后倾 `16°`（切线方向再 +0.28 rad）。

### 3.4 `antenna`（A 家族）

- 两段：基部 `(0,0)→(5,12)`，末端 `(5,12)→(12,22)`（+y 向上）；线宽 `2.2U` → `1.4U`。
- 末端一个小球 `r 2.4U`，填充 `#f2b24b`，带 `shadowBlur 6` 的微光。
- 摆动见 §4.4；根点固定，只动两段的角度。

### 3.5 四肢：`leg` / `longleg` / `claw` / `fin`

四种共用**同一套关节骨架**，只是长度与末端不同：

| 零件 | 大腿 a | 小腿 b | 总够到 R=a+b | 末端 |
|---|---|---|---|---|
| `leg` | 16U | 17U | 30.8U | 脚掌 `8 × 3.2` 椭圆 |
| `longleg` | 22U | 23U | 42.0U | 脚掌 `9 × 3.4`，小腿再分一节"胫"（见下） |
| `claw` | 14U | 15U | 27.1U | 3 枚爪尖，各长 6U，扇形 -30°/0°/+30° |
| `fin` | 11U | 10U | 19.6U | 鳍蹼：半椭圆 `16U × 8U` |

> `U = H/48`。腿长**必须随体厚缩放**，否则 3 个零件时腿长到身体外面、
> 12 个零件时腿短得看不见。参考：H=44.8 时 `leg` 的 R≈30.8（约 0.69H），
> 走起来脚底板离地 13~15px，正好够看清髋/膝/踝三个关节。

**画法（以 `leg` 为例，全部乘 U）**

1. 髋关节盖：圆 `r 3.2`，填充 `#16302e`，描边 `#46c8b2`，画在身体**之后**，
   让关节看起来嵌进体壁。
2. 大腿：`ctx.lineWidth = 4.4U`，`lineCap='round'`，从髋到膝 `stroke()` 一条线
   —— **粗圆头线就是胶囊，不要用 roundRect**（每帧省 2 次路径构造）。
3. 膝关节：圆 `r 2.8U`，填充 `#0f2321`，描边 `#46c8b2 0.9`。
4. 小腿：`lineWidth = 3.2U`，膝→踝。
5. 踝：圆 `r 2.2U`。
6. 脚掌：椭圆 `8 × 3.2`，中心在踝下方 `1.3U`，填充 `rgba(70,200,178,0.22)`，
   描边家族色。`claw` 换成 3 枚三角形爪尖；`fin` 换成鳍蹼（见下）。
7. 高光：沿大腿上缘画一条 `rgba(157,240,224,0.35)`、`1U` 的短线，长度 = 大腿 60%。

`longleg` 的小腿再分一节：`a=22U`，`b` 拆成 `12U + 11U`，中间关节固定 `+0.18 rad`

## 4. 动画（全部由 `t`（秒）+ 相位驱动）

**总原则**
- 时间单位是**秒**，从 `state.now / 1000` 得到；禁止用帧计数、禁止 `setTimeout`。
- 所有周期写成 `sin(TAU * t / T + phase)`，`TAU = Math.PI * 2`。
- `state.runPhase`（0..1）只用于和舞台的跑步进度对齐；**步态相位一律用 `t/T` 现算**，
  不要拿 `runPhase` 当相位（它会在每次起跑时归零，腿会"跳"一下）。
- 同一帧里只算一次 `Math.sin/cos` 需要的相位，别在循环里重复展开。

### 4.1 步态：用 IK 驱动，脚必须踩在地上

**参数（直接抄）**

```
T  = 0.62 s          // 步态周期（奔跑）
D  = 0.62            // 支撑相占比
S  = 0.66 * R        // 步幅（R = 该条腿的 a+b；短腿自然走得碎）
LIFT_SWING = 8 * U   // 摆动相抬脚高度
BOB = 1.6 * U        // 身体上下起伏幅度
```

**每条腿的相位**（`j` = 腿在腹侧的序号，从前数；`i` = 该零件的全局 `index`）

```
φ_j = frac(j * 0.5 + j * 0.07)     // 对角步态 + 每对之间的 7% 漂移
// frac(x) = x - Math.floor(x)，必须用 floor（不能用 x % 1，负数会错）
p   = frac(t / T - φ_j)            // 0..1，当前腿自己的相位
```

`j=0,1,2` 时 `φ = 0, 0.57, 0.14`；`m=2` 时 `0, 0.5`；`m=4` 时 `0, 0.57, 0.14, 0.71`。
7% 漂移的作用：避免所有腿像节拍器一样整齐，看起来更"活"。

**脚掌目标轨迹**（髋局部坐标：+x 向前，+y 向下）

```
hipH = lift(t) - 0.26*H            // 髋到地面的距离，随身体起伏变化

if (p < D) {                       // 支撑相：脚钉死在地面
  fx = S * (0.5 - p / D);
  fy = hipH;
  grounded = true;
} else {                           // 摆动相：抬起、前摆、落下
  u  = (p - D) / (1 - D);
  fx = S * (-0.5 + smoothstep(u));
  fy = hipH - LIFT_SWING * sin(PI * u);
  grounded = false;
}
```

**两骨骼 IK（大腿 a、小腿 b）**

```
d   = clamp(hypot(fx, fy), abs(a - b) + 1, a + b - 1);
dir = atan2(fx, fy);                       // 0 = 垂直向下，正 = 向前
β   = acos(clamp((a*a + d*d - b*b) / (2*a*d), -1, 1));
ψ   = dir + β;                             // 大腿方向（+β 让膝盖朝前，像昆虫）
K   = ( a*sin(ψ), a*cos(ψ) );              // 膝点
F   = ( fx, fy );                          // 踝点 = 目标
flex = PI - acos(clamp((a*a + b*b - d*d) / (2*a*b), -1, 1));  // 膝弯曲量（0=直腿）
```

- 画：`髋 → K` 一段粗线，`K → F` 一段粗线；`F` 处画脚掌，角度 `grounded ? 0 : -0.35*sin(PI*u)`。
- 支撑相不改 `fy`，所以**身体起伏时腿会自动屈伸，脚始终贴地**——这是"会走路"的关键。
- 待机时 `p = frac(0.35 + 0.05*sin(TAU*t/3.2 + j))`，腿几乎不动，只有轻微换重心。

**身体起伏与相位关系**

```
liftBase = 0.26*H + 0.80*R_median        // R_median = 所有腿 a+b 的中位数
bob(t)   = BOB * sin(TAU * 2 * t / T + 0.6)   // 一个步态周期里起伏两次
lift(t)  = liftBase + bob(t)             // +y 向下，所以正值 = 身体下沉
```

- 头部滞后：`headNod = 0.02 * sin(TAU*t/T - 1.1)`（rad），
  头部位置额外 `-1.2*U*sin(TAU*2*t/T - 0.35)`（慢半拍，产生"追随"感）。
- 尾巴：`tailRot = 0.05 * sin(TAU*t/1.3)`。
- 奔跑时整体前倾 `+0.07 rad`（约 4°），停下时缓慢回正（时间常数 0.25 s）。

### 4.2 不同运动方式

| locomotion | 身体抬升 | 腿 | 额外 |
|---|---|---|---|
| `walk` | `0.26H + 0.80R + bob` | 步态循环 | 尾巴左右摆 |
| `fly` | `0.26H + 0.80R + 0.95H + 2*sin(TAU*t/2.4)` | 收起：髋后转 0.66 rad、膝弯 0.9 rad | 翅膀扇动（§4.4），身体 `sin(TAU*t/2.4)*3*U` 上下浮沉 |
| `mixed` | `0.26H + 0.80R + 0.30H` | 步态循环（幅度 ×0.7） | 翅膀以 0.5 幅度扇 |
| `swim` | `0.26H + 0.40R` | 腿向后拖 | 脊柱行波：每节 `y += 2.2U*sin(TAU*(s*1.6 - t/1.15))`，水纹见既有实现 |
| `none` | `0.5H * 0.92` | 无 | 蠕动：每节 `y += 1.4U*sin(TAU*(s*1.6 - t/1.8))`，周期 1.8 s |

### 4.3 待机微动画（没有这些就"死"了）

| 动作 | 周期 | 幅度 | 公式 / 说明 |
|---|---|---|---|
| 呼吸 | 3.2 s | ±2.2% | 身体 `scaleY = 1 + 0.022*sin(TAU*t/3.2)`，`scaleX = 1 - 0.010*sin(...)`；胸腔（s≈0.62）额外 `+0.6U` |
| 眨眼 | 4.4 s | 0 → 1 | `bp = t mod 4.4`；`blink = bp > 4.24 ? sin(PI*(bp-4.24)/0.16) : 0`；眼睑从上方盖下，`17.2*U * blink` |
| 二次眨眼 | 每 3 个周期 | 同 | `floor(t/4.4) % 3 === 2` 时，再补一次 `blink*0.7`，间隔 0.22 s（可选） |
| 鳃颤动 | 0.54 s | ±12% | 第 k 条缝 `scaleY = 1 + 0.12*sin(TAU*(t - 0.11k)/0.54)` |
| 发光脉冲 | 2.6 s | α 0.55→0.95 | `g = 0.5+0.5*sin(TAU*t/2.6)`；光晕半径 `×(1+0.08*g)`，`shadowBlur = 10 + 10*g` |
| 触角摆动 | 1.9 s | ±0.13 rad | 根节 `angle = 0.13*sin(TAU*t/1.9)`；末节滞后 0.13 s、幅度 ×1.7 |
| 鳍波动 | 1.1 s | ±0.12 rad | 3 段，逐段滞后 0.22 s |
| 气囊鼓动 | 3.2 s | +6% | 与呼吸同周期，相位 +0.25 周期 |
| 身体重心 | 5.1 s | ±0.6U | 整只生物左右微移 `0.6U*sin(TAU*t/5.1)`（待机时的"活着"感） |

### 4.4 翅膀

```
Tw   = locomotion === 'fly' ? 0.34 : (running ? 0.42 : 0.52)   // s
amp  = locomotion === 'fly' ? 0.62 : (running ? 0.40 : 0.12)    // rad
ω    = TAU * t / Tw
angle = -0.22 + amp * sin(ω)          // 绕肩旋转；-0.22 = 静止时的后掠角
```

- 膜的远端（§3.9 的翼膜外缘点）滞后 `0.09 s`：
  `angleFar = -0.22 + amp * sin(ω - TAU*0.09/Tw) * 1.15`。
- 扇到最高点时整个翅膀 `scaleY *= 0.92`（透视收缩），制造"翻面"的错觉。
- 两侧翅膀（`m=2`）相差 `0.5` 周期，看起来像在"抖"；`m=1` 时直接扇。

### 4.5 状态与特殊形态

| 状态 | 表现 |
|---|---|
| `growth` 0→1 | 零件从锚点 `scale 0→1`（`easeOutElastic`，340ms），已在既有 `stage.ts` 实现，保留 |
| `highlight = 1` | 该零件外发光：`shadowColor = 家族色, shadowBlur = 14, alpha 0.5`，同时 `scale ×1.06` |
| `fracture`（no_stop） | 身体在 `s≈0.18` 处断口：删除该处之后的所有体节，断口画锯齿边 + 红色 `#ff6b7a` 内发光 |
| `alpha` | 整体乘 `state.alpha`，用于淡入淡出 |
| `tilt` | 整体绕脚底旋转，失败时用（`±0.12 rad`） |

## 5. 镜头与比例

### 5.1 舞台缩放

现有 `creatureScale = clamp(min(w/820, h/370), 0.58, 2.25)`。
建议改为（生物变大后要给一点余量）：

```ts
private get creatureScale(): number {
  return clamp(Math.min(this.width / 760, this.height / 350), 0.62, 2.2);
}
```

| 画布 | scale | 8 零件生物（L=209） | 眼睛外径（17.2U） | 大腿粗（4.4U） |
|---|---|---|---|---|
| 930 × 527 | 1.22 | 256 px | 19.6 px | 5.0 px |
| 700 × 420 | 0.92 | 192 px | 14.8 px | 3.8 px |
| 375 × 520 | 0.62（下限） | 130 px | 9.9 px | 2.5 px |

结论：**375 宽也能读出眼睛和腿的关节**（眼睛 ≈10px、腿粗 ≈2.5px）。
若低于这个值，说明 `creatureScale` 的下限被改小了，不要动。

### 5.2 地面基线与站位

- 地面 `groundY` 保持不变（`height - max(64, min(112, height*0.18))`）。
- 生物的**脚底**必须正好落在这条线上：局部 `y=0`，`translate(x, groundY)`。
- 起跑位置 `x = trackX0 + 40`；终点 `trackX1 - 20`。
- 生物占轨道长度的上限：`L*scale ≤ 0.42 * (trackX1 - trackX0)`。
  12 个零件时（L=264, scale 1.22 → 322px）会逼近上限，此时**不要**缩生物，
  改为让生物在跑道上稍微偏左起跑。

### 5.3 结算卡 / 预览缩略图

缩略图（`preview.ts` 与 `app.ts` 的结算卡）用同一个 `drawCreature`，`scale` 约 0.3~0.9。
必须按**有效像素**降级：

```ts
const effH = H * scale;                    // 生物在屏幕上的实际高度
const lod = effH >= 26 ? 2 : effH >= 14 ? 1 : 0;
```

| LOD | 条件 | 画什么 |
|---|---|---|
| 2 | effH ≥ 26 | 全部细节 |
| 1 | 14 ≤ effH < 26 | 去掉膜纹、牙齿、高光线、眨眼；描边统一 `1px`；保留发光 |
| 0 | effH < 14 | 只剩**剪影**：身体 + 四肢粗线 + 每家族 1 个色点；不画描边（描边会糊成一团） |

LOD 0 的关键：**别画细节，画轮廓**。把身体和腿合并成一条深色路径，让"有腿/有翼/有甲"
的剪影可辨即可。

## 7. 程序化实现要点

### 7.1 数据结构（`buildCreature` 返回，**每帧只读**）

```ts
export interface CreatureLayout {
  readonly n: number;
  readonly L: number;          // 体长
  readonly H: number;          // 体厚
  readonly U: number;          // H / 48
  /** 体节（数量 Nseg），全部预计算，尾→头顺序。 */
  readonly segX: Float32Array;
  readonly segY: Float32Array;
  readonly segRX: Float32Array;
  readonly segRY: Float32Array;
  readonly segRot: Float32Array;
  /** 每个零件在脊柱上的落点。 */
  readonly anchors: readonly Anchor[];
  /** 四肢的静止参数（a/b/相位），每个腹侧肢体一条，顺序 = 腹侧 j 顺序。 */
  readonly limbs: readonly LimbRest[];
  /** 走路基准抬升（H、零件数决定，和 bob 无关）。 */
  readonly liftWalk: number;
}

export interface Anchor {
  readonly partIndex: number;   // Part.index
  readonly id: PartId;
  readonly family: Family;
  readonly s: number;           // 脊柱参数
  readonly x: number;           // 局部坐标（已含 0.26H 内缩）
  readonly y: number;
  readonly rot: number;         // 切线角 + 零件自身偏转
  readonly flip: boolean;       // 需要 scale(1,-1) 的零件：背侧 + 头顶
  readonly size: number;        // 参考尺寸 × U
  readonly j: number;           // 类别内序号
  readonly m: number;           // 类别内总数
}

export interface LimbRest {
  readonly a: number;
  readonly b: number;
  readonly reach: number;       // a + b
  readonly phase: number;       // φ_j
  readonly j: number;           // 腹侧序号（从前数）
  readonly far: boolean;        // 远侧（先画、压暗到 65%）
}
```

> `segX..segRot` 用 `Float32Array` 而不是对象数组：9~13 个体节，每帧遍历两次，
> 用 typed array 能少一次 GC 压力，也方便在 `for` 里直接下标访问。

### 7.2 预计算 vs 每帧

| 只算一次（`buildCreature`） | 每帧算（`drawCreature`） |
|---|---|
| `H, L, U, Nseg` | `t`、呼吸、眨眼、脉动相位 |
| 脊柱采样 `sx/sy/tan`（33 点） | 每条腿的 `p / fx / fy / IK` |
| 体节中心、半径、旋转 | 翅膀角度、膜滞后 |
| 每个零件的 `s / 锚点 / rot / flip / size` | `bob`、`lift`、头滞后、尾巴 |
| 四肢的 `a/b/reach/phase` | `growth`、`highlight`、`alpha` 的取值 |
| `liftWalk`、`R_median` | 身体渐变（可缓存，见 §7.3） |

### 7.3 三个必须做的缓存

1. **身体精灵缓存**
   体节 + 头 + 节间缝在 `(L, H, n)` 不变时是静态的。
   用 `OffscreenCanvas` 画一次（尺寸 `(L+2*PAD) × (H+2*PAD)`，`PAD = 12*U`，
   按 dpr 放大），之后每帧只 `drawImage`。
   呼吸、前倾这些**用变换实现**（`ctx.scale(1, 1+0.022*sin)`），不要重新生成。
   缓存 key：`` `${L|0}:${H|0}:${n}` ``；`phenotype` 变化时才重建。

2. **`Path2D` 常量路径**
   甲的弧、刺的三角、鳍的蹼、爪的尖，都做成模块级 `Path2D`
   （单位尺寸 1×1 或 32×32），绘制时 `ctx.translate/rotate/scale` 后 `fill(path)`。
   **不要**每帧 `new Path2D()`。

3. **渐变对象**
   身体渐变按 `(L,H)` 缓存成一个；发光器的径向渐变按半径缓存。
   60fps 下每帧创建 4 个以上渐变就会开始掉帧（Chrome，1080p）。

### 7.4 `drawCreature` 伪代码

> 现实签名比 `drawCreature(ctx, phenotype, t, scale)` 多两个参数：
> `layout` 是 `buildCreature(phenotype)` 的**预计算结果**（§7.2），
> `t` 从 `state.now / 1000` 取。这样每帧不做布局，只做姿势。

```ts
const TAU = Math.PI * 2;

export function drawCreature(ctx, layout, x, groundY, scale, state) {
  if (layout.n === 0 || state.alpha <= 0.001) return;

  const t = state.now / 1000;
  const U = layout.U;
  const H = layout.H;
  const loco = layout.locomotion;
  const running = state.running;
  const lod = lodOf(H * scale);

  // ---- 1. 时间量（一帧只算一次）----
  const breath = Math.sin(TAU * t / 3.2);
  const bob = (loco === 'walk' || loco === 'mixed')
    ? 1.6 * U * Math.sin(TAU * 2 * t / 0.62 + 0.6) : 0;
  const lift = liftOf(layout, loco, bob, t);   // §4.2 的表
  const blink = blinkOf(t);                    // §4.3

  // ---- 2. 变换（一次到位）----
  ctx.save();
  ctx.translate(x, groundY);
  ctx.scale(scale, scale);
  if (state.tilt) ctx.rotate(state.tilt);
  ctx.globalAlpha *= clamp(state.alpha, 0, 1);

  // ---- 3. 地面投影（在最下面）----
  drawShadow(ctx, layout.L, lift, H);

  // ---- 4. 身体整体坐标 ----
  ctx.save();
  ctx.translate(0, -lift);        // 现在原点 = 身体中心
  ctx.scale(1 - 0.010 * breath, 1 + 0.022 * breath);

  // ---- 5. 远侧肢体（压暗、先画）----
  {
    const a0 = ctx.globalAlpha;          // 存旧值，别用 /= 0.65 还原（会漂）
    ctx.globalAlpha = a0 * 0.65;
    for (const limb of layout.limbs) if (limb.far) drawLeg(ctx, layout, limb, t, state, lod);
    ctx.globalAlpha = a0;
  }

  // ---- 6. 身体（缓存精灵）----
  drawBodySprite(ctx, layout, lod);

  // ---- 7. 近侧肢体 / 背甲 / 尾器官 / 头 ----
  for (const limb of layout.limbs) if (!limb.far) drawLeg(ctx, layout, limb, t, state, lod);
  drawAnchoredParts(ctx, layout, t, state, lod, /*layers*/ ['back', 'rear', 'front']);

  // ---- 8. 发光叠加（最后，lighter）----
  ctx.globalCompositeOperation = 'lighter';
  drawGlowOverlay(ctx, layout, t, lod);
  ctx.restore();

  ctx.restore();
}
```

**绘制顺序（从后到前）**：投影 → 远侧腿/翼 → 身体精灵 → 近侧腿 → 背甲/刺/冠 →
尾器官 → 头/眼/角/触角 → 发光叠加。

### 7.5 性能预算（930×527 CSS，dpr 2，60fps）

| 项 | 上限 |
|---|---|
| 每帧 `Path2D` 新建 | 0 |
| 每帧渐变新建 | ≤ 3（超了就是没缓存） |
| `shadowBlur` 绘制次数 | ≤ 2（发光器 + 断口） |
| `ctx.save/restore` 配对 | ≤ 40 对 |
| 每帧总绘制调用（fill+stroke） | ≤ 260 |
| 单帧 CPU | ≤ 4 ms（留 12 ms 给浏览器） |

超预算时的降级顺序：膜纹 → 牙齿 → 趾尖 → 节间缝 → 高光线。

### 7.6 常见翻车点（照着躲）

1. **`globalAlpha` 累积**：远侧肢体用了 `*= 0.65` 之后忘了恢复，后面整只生物发灰。
   用 `ctx.save/restore` 包住，或先存旧值再还原。
2. **`lineWidth` 被 scale 影响**：进入局部坐标后 `lineWidth` 是局部单位，
   1.4U 在 scale=1.22 时是 1.7 屏幕 px；**不要**再乘 dpr。
3. **IK 的 `d` 没有 clamp**：步幅稍大时 `acos` 的入参超出 `[-1,1]` 会返回 `NaN`，
   整只生物消失。三处 `acos` 全都必须 `clamp`。
4. **`atan2(fx, fy)` 参数顺序写反**：本规格约定 `0 = 正下方`，
   写成 `atan2(fy, fx)` 会让腿横着长。
5. **身体精灵的 dpr**：`OffscreenCanvas` 必须按 `dpr` 建，
   `drawImage` 时目标尺寸用 CSS 尺寸，否则高 dpi 下身体糊成一团。
6. **体节描边-填充顺序颠倒**：先填充再描边，会让每一节都有黑边，像条蜈蚣。
7. **眨眼时瞳孔消失**：眼睑盖下来的同时瞳孔位置要冻结，否则会"翻白眼"。
8. **`prefers-reduced-motion`**：`state` 里没有这个标志时，
   用 `prefersReducedMotion()`（`anim.ts` 已有）把步态/扇翅的速度降到 0，只保留呼吸。

## 8. 文字版分镜：三条腿走路（自检用）

参数：`H = 44.8`，`U = 0.933`，`T = 0.62 s`，`D = 0.62`，`S = 20.3`，`hipH ≈ 24.8`。
三条腿 `j = 0/1/2`（从前到后），`φ = 0 / 0.57 / 0.14`，`a = 14.9, b = 15.9`（即 16U/17U）。
下表里的 `fx` 是**脚相对髋的前后偏移**（+ 向前），`flex` 是膝弯曲量，`抬` 是脚离地高度。

| 帧 | t (s) | 腿0 (φ=0) | 腿1 (φ=0.57) | 腿2 (φ=0.14) | 身体 |
|---|---|---|---|---|---|
| ① 触地瞬间 | 0.000 | p=0.00 **支撑**，fx=+10.2，flex 54° | p=0.43 **支撑**，fx=−3.9，flex 66° | p=0.86 **摆动**，fx=+3.9，抬 6.8，flex 104° | bob=+0.84（下沉段），头略前倾 |
| ② 中段推进 | 0.155 | p=0.25 **支撑**，fx=+2.0，flex 78° | p=0.68 **摆动**，fx=−8.8，抬 3.6，flex 88° | p=0.11 **支撑**，fx=+6.6，flex 74° | bob=−0.84（抬高段），头抬起 |
| ③ 换脚 | 0.310 | p=0.50 **支撑**，fx=−6.2，flex 63° | p=0.93 **摆动**，fx=+8.3，抬 4.1，flex 84° | p=0.36 **支撑**，fx=−1.6，flex 68° | bob=+0.84，头下沉 |
| ④ 后蹬离地 | 0.465 | p=0.75 **摆动**，fx=−4.7，抬 6.6，flex 109° | p=0.18 **支撑**，fx=+4.3，flex 77° | p=0.61 **支撑**，fx=−9.8，flex 67° | bob=−0.84，整体前倾 0.07 rad |

**读法**：
- 任意时刻**至少两条腿在地面**（三足步态的自然结果），不会出现"悬空"。
- 每条腿按 0 → 0.62 是支撑（脚从 +10.2 匀速滑到 −10.2，贴地），0.62 → 1 是摆动
  （抬 8U 高、快速前摆、落地）。
- 支撑相里 `fx` 是**匀速**的（不是正弦），所以脚掌不会在地上打滑——这一点最重要：
  **如果脚在支撑相里速度不均匀，看起来就是在溜冰。**
- 帧①→④，腿0 从最前到抬离地面，正好走完一个相位；把它连起来看应该是
  "落地 → 压过身体下方 → 后蹬 → 抬起 → 前摆"。

**快速自检**：把 `t` 停在 0，逐帧按 0.05 s 推进并截图；
如果任意一帧里脚掌离地（y < 地面 − 0.5）而该腿处于支撑相，就是 IK 或 `hipH` 写错了。
